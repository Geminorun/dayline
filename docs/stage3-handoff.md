## 实现范围

- Web：默认 `/day`，每日回看、全部记录、时间轴、分类、回收站、设置六导航；独立新建 / 详情路由，保留 `/review`、旧账号 / 认证地址兼容。日期选择、周一到周日、前后日 / 今天、指定日重点、CRUD / 今天结束、30 天恢复 / 永久清理、分类增改和原子转移均可操作。新开详情深链有安全站内返回；视图筛选、锚点和滚动状态保持，未保存输入有离开确认，取消离开后保存仍可正常返回，不重复要求放弃已提交输入。认证路由按 path 重新挂载，密码、reset token 与 QR 定时器不跨模式复用，`/auth/verify-email` 映射实际验证表单。
- 小程序：回看、记录、时间轴、我的四 tab，以及独立事项编辑、分类、回收站页。业务并非只读概览；全部核心操作有独立触控表单 / 确认。旧 `pages/account/index` 只兼容跳转到“我的”，不保留第二套账号状态。真实扫码页面仍为 `pages/scan/confirm`，与后端配置一致。没有增加假微信登录 / 假二维码。
- 两端有标题搜索、分类 / 当前状态组合筛选、开始日期升降序及稳定 ID 次序；统计来自完整筛选集合，明确区分选定日事项、今天仍在进行、涉及分类与按事项数量分布。搜索词不进入 URL。首次失败与真正空数据 / 筛选无结果分开。没有向正式游客包加入演示数据。
- 两端时间轴支持月 / 季度 / 年 / 全部、前后自然窗口与定位今天。共享序数、半开窗口、含首尾横条、区间裁剪、重点分组与可见行几何；两端分别渲染。固定名称与时间头、横向滚动、统一 56 px 行高及虚拟行；季度重点按周一分周、年按月，极长区间有界刻度与相邻像素碰撞聚合。非密集重点保留真实日期位置，聚合详情保留全部真实日期并分页浏览，可点入回看。今天线、未来开始标记、已知结束完整计划跨度和无结束已开始到今天分别计算。筛选从深滚动缩成 1 / 0 项时夹取滚动 / 虚拟索引，不留下空白大占位。
- 配色采用规格的背景 / 紫色 / 面板 / 边线与系统字体，桌面侧栏和小程序触控布局独立。事项显示分类名称及对应色点，时间轴名称边线 / 横条随分类颜色变化。未来无结束显示“结束未定 / 未开始”，不虚构已持续天数。危险操作明确确认，错误持续可见，网页使用语义表单 / 按钮和键盘可达控件；重点选中态补足白色文字对比。

## 游客数据及提交边界

`packages/contracts/src/guest.ts` 定义严格游客包和纯不可变变更规则；沿用既有 core → contracts → api-client 的单向依赖，core 没有反向导入 contracts。`GuestPackage` 含独立 UUID `guestDatasetId`、`packageRevision`、本机 / 包 schema、保存时间、分类、事项（含回收站）和 true / false 重点，无认证凭据。读入校验重复 ID / 分类名、引用、日期范围、删除配对及 true 重点有效范围；未知 schema / 损坏停止覆盖并保留原始内容。

六个默认分类只在首次初始化生成 UUID，不因数量减少重新补齐。`mutateGuest` 覆盖事项 / 分类 CRUD、单日重点独立版本、精确重点移除确认、分类正常与回收站项转移、恢复 / 部分或全部清理 / 30 天过期清理。失败不修改调用方的原包；新建失败保持稳定 ID，日期范围和重点移除在同一次提交内完成。启动、游客回前台和手动重读进行过期清理；恢复本身仍严格检查到期，后台不运行时不会延长 30 天。

- Web：Dexie 4.2.1 / IndexedDB，当前完整游客包独立于账号数据。事务内读取当前修订与数据集，再 CAS 写入；等待事务 complete 后更新正式 UI / 显示已保存。多标签同基准只有一个胜者，失败方保留输入并可重新完整读取。损坏包不会被默认空包覆盖。
- 小程序：独立 `KeyStorage` 适配，不将完整历史塞入单个巨键。每片最多 180,000 UTF-16 单元，按 UTF-8 最坏情况约 540 KiB；先写完 / 回读验证新的不可变代次，最后单键提交带 schema、数据集、修订、分片数、长度与校验值的 manifest。切换前再比较当前修订，失败保持上一份完整 manifest / 代次。成功后只清理当前环境自己的旧代次；凭据、其他环境与其他应用键不会清除。容量不足在写入前明确拒绝，不悄悄腾空旧游客数据；没有 manifest 却发现孤立分片时进入恢复状态。
- 小程序新 UUID 使用 `wx.getRandomValues` 字节生成；没有安全随机源时明确提示更新微信 / 重试，未退回 Math.random 作为认证或业务 ID。实际微信随机源、存储回调耐久与低空间表现仍需真机验证。

数据空间默认为游客；存在 Cookie 不强制切换，也不会自动搬入账号。明确登录 / 进入已验证账号后在线保存，继续游客只切换空间，退出返回原游客包。当前有基本空间代次屏障和读取合并，防迟到的游客读取覆盖已切换空间；完整账号生命周期 / dataVersion 协调仍由阶段 4 承接。

## 显示名资料接口

新增受保护 `PATCH /api/v1/me`，只接收 `{ displayName, expectedProfileVersion }`；共享 schema 严格校验 1–40 个 Unicode 码点与版本。服务事务先锁 users 行，再复核 actor epoch / active 状态 / 原 profileVersion；同基准竞争只有一笔成功，旧版本返回 409，额外字段 / 无版本返回 422，同名不增加版本。成功返回公开 UserDto；资料更新不改变业务 dataVersion。

未绕开原有会话、Origin、预期账号与 uni POST + `X-Dayline-Method-Override: PATCH`。原生 `/api/auth/update-user` 等绕过业务资料版本的路径仍 404。两个设置页均按原 profileVersion 提交，失败保留输入，提供重新读取 / 核对路径。
