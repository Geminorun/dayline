# Web / PWA

PWA 位于 `apps/web`，和网页共用 Vue 界面、邮箱认证及业务 API。通过现有 Web + API 镜像和 `server.yml` 一起发布，无需新服务器、商店账号或额外 Secret。

## 安装与使用

1. 部署后用 HTTPS 打开站点，首次联网访问完成页面缓存。
2. Chrome / Edge 从头像菜单或“设置 → 外观 → 日序应用”安装；支持安装提示时调用浏览器原生安装框，否则提供操作说明。
3. iPhone / iPad 用 Safari 的“分享 → 添加到主屏幕”。桌面图标打开即为独立应用；系统是否共享普通浏览器会话取决于平台，必要时重新登录同一账号。
4. 手机端使用紧凑顶栏、底部“每日回看 / 时间轴”导航，并适配安全区域与触屏控件。语言、主题继续使用现有配置。

## 缓存和数据边界

- 使用 `vite-plugin-pwa` / Workbox 预缓存构建时的 HTML、JS、CSS、图标和拆分模块。约 1.2 MB，具体以构建日志为准。
- 不缓存 API、认证响应、邮件令牌、导入导出文件、健康检查或诊断日志；请求失败也不会回退成 HTML。导航只回退到公共页面入口，不保存访问地址中的查询参数。
- 游客数据、账号快照和草稿继续由原有 IndexedDB 适配器管理，沿用账号隔离与冲突检查。Service Worker 不存储业务响应，也不提交业务请求。
- 游客可以离线记录；账号登录、云端保存和同步需要联网，草稿仍手动提交。离线冷启动无法确认账号身份时，须显式选择“继续游客”才能进入本机游客记录；恢复联网后重新确认账号，不以页面缓存绕过身份检查。
- 浏览器清理站点数据也会清除缓存及本机内容；仅已保存到云端的数据可以登录后找回。PWA 不是额外备份渠道。

## 更新与运维

- 页面加载后注册根路径 `/sw.js`，回到前台或恢复联网时检查更新，检查间隔至少一分钟。
- 新版本提示“更新 / 稍后”；用户确认后才激活并刷新当前窗口。事项编辑器先完成草稿暂存，无法暂存的修改沿用离开确认。其他表单需先保存，其他窗口不会自动刷新，也会提示更新。
- 推迟更新后仍可在设置中更新。更新失败可以重试；首次缓存失败不会阻止正常网页访问。
- `index.html`、`sw.js`、`manifest.webmanifest` 必须保持新鲜，现有 API 静态服务统一返回 `Cache-Control: no-store`；带哈希的 `/assets/` 使用 immutable 缓存。Nginx / Cloudflare 不要额外开启 HTML 或 Service Worker 的强制缓存。
- 如紧急撤回 PWA，先通过同一路径发布用于注销的 Service Worker，再移除注册入口；只删除 `/sw.js` 不会立即清掉已有设备的控制器。注销缓存不能删除业务 IndexedDB。

## 验证

- `pnpm --filter @dayline/web build` 会生成 manifest、Service Worker 和图标，并校验安装尺寸、全部拆分资源预缓存及静态资源白名单。
- 单元测试覆盖原生安装提示、缓存失败、离线、更新确认、跨窗口激活和草稿刷新保护；API 测试覆盖 worker / manifest 的 MIME、缓存头和缺失资源。
- 发布验收：检查手机导航与设置、安装后独立启动、断网重新打开及游客记录、联网账号保存、新版本提示及多窗口编辑。iOS 的实际安装和安全区域效果需在真机 Safari 验收。
