日期：2026-10-26。实现 Agent 未提交、推送或发布，根计划及提交由主 Agent 维护。本阶段新增 `20261026172254_import_jobs`，按当时真实 UTC 命名并使用显式事务；既有三个迁移、旧库及数据卷没有 reset、drop 或历史改写。

## 实现范围

- 两端应用启动统一恢复已有会话，明确游客偏好优先。先验证 `/me`，才加载该账号的缓存；身份未知或失效隐藏私人内容，提供重新验证 / 登录 / 明确继续游客。恢复会话只读取，显式登录后的游客接入另行编排。`ApiClient.confirmAccount` 不因相同账号的正常 `/me` 增加代次，显式重新登录仍建立新代次。401、expected-user mismatch、退出、密码重置及最小跨标签事件都使旧请求失效；跨标签事件不携带身份凭据或私人内容。
- 纯 `SnapshotCoordinator` 协调两端完整 GET、304、账号 / 空间代次和十进制版本下界；平台各自处理前台约 30 秒、focus / onShow、网络恢复及后台停止。重叠读取合并，最多保留一次后续读取意图。网络恢复仅 GET，没有自动 POST / PATCH / DELETE、离线写队列或 Redis。
- 完整缓存、已确认写入的可见字段与写入版本下界分别处理：局部 V12 回执不会把缺少他端 V11 的旧完整 V10 伪装成完整 V12。只有完整 GET 持久化新版本；较旧 GET / 回执、迟到缓存和旧账号回调不得倒退当前状态。缓存写串行；重新认证的首个可信在线基线可低于旧本机版本。服务器 `/me` / 响应时间校准今天，旧缓存时间不重当此刻，跨北京时间午夜更新派生视图并重新读取。
- Web 账号缓存 / 草稿 / 冻结操作采用独立 IndexedDB 账号仓库，事务完成后才显示持久成功；小程序账号快照及冻结操作采用不可变分片、校验和、回读及最后 manifest 提交，凭据保留独立键。信封同时校验 schema、环境、所属账号、键内 ID、complete、日期 / 引用 / 活动与回收站分区。损坏原文保留并停止覆盖；云端确认与本机缓存 / 凭据失败分别反馈。
- Web 新建 / 编辑草稿保留原账号、独立 draftId、稳定 entryId、原始基准快照 / 版本、inputRevision / persistedRevision、暂存时间和未完成输入。约 300 ms、失焦与路由离开 flush；身份失效前最后输入仍写原账号命名空间。刷新不改表单和基准。保存前冻结完整请求；保存 / 草稿清理期间新输入保留，自己的确认可作为新输入基准，外部 GET 不重设基准。恢复草稿生成独立分支，不覆盖另一标签草稿；继续编辑链接仅带草稿 UUID，实际内容不进入 URL；本标签会话指针记录成功持久的当前恢复分支。暂存 / 离开 flush 不触发路由导航，避免取消用户正在离开的目标。原恢复来源保留，只有列表中的明确放弃操作才清理原稿。
- `/drafts` 仅在明确账号空间且重新确认同一账号后显示，可继续、复制、下载单份 `dayline-draft` 或明确放弃；切游客 / 换账号立即隐藏，并阻止迟到读取重新显示。草稿不计入正式统计或云端备份。存储失败持续提示并保留输入。
- Web 冲突表显示中文字段、云端当前内容、草稿和差异，分类显示名称 / 色点，空结束日显示“未结束”。可放弃用服务器、核对后按当前版本保存、明确另存副本或暂不处理。删除 / 物理清理不把 PATCH 降级 CREATE。Web 与小程序的新增 `alreadyExists` 核对实际字段；结果不明先 GET 核对，重试保留稳定 ID。小程序账号输入仅保留当前页面内存，没有持久草稿承诺。

## 接入及下一阶段接口

`POST /guest-admissions/prepare` 使用独立 10 MiB JSON 解析，最多 10,000 事项 / 100,000 重点。输入按格式、UUID、引用、日期、数量、时钟及回收站状态校验。超过服务器 5 分钟的操作时间、未来真实重点或不等于连续 30 天的删除期限受控拒绝，要求先校准 / 核对原包；已合法到期回收站来源明确跳过，不恢复为活动事项或延长期限。

任务持久于 `import_jobs(kind=guest)`。空账号判定在用户锁下检查全部事项、回收站、重点及六个完整默认 seed / 名称 / 颜色；不能只看事项数。真正空且无歧义时同事务直接 committed；其他情况返回 preview_required，预览本身无业务写入。分类完全匹配时复用，同名异色需明确改名或映射；20 类上限不可通过丢弃解决。同名事项默认保留双方。

- `ImportsService.prepareNormalized(actor, kind, clientOperationId, source, autoIfEmpty)` 是阶段 5 的服务端解析后入口。`NormalizedImportSource` 为纯契约，含稳定 sourceNamespace / sourceRevision、分类、事项、重点及来源时间；它不携带授权。CSV / JSON 解析层扩展行级更新 / 恢复决策时继续使用本服务的持久计划、review 与同一提交事务，不另写另一套 commit。
- 通用 `GET /imports/:id`、`GET /imports/by-operation/:operationId`、`POST /imports/:id/review`、`POST /imports/:id/commit` 与 DELETE 取消均已开放。review 产生新修订 / 摘要且保持稳定 candidate ID；提交按用户后任务顺序加锁，再验 epoch、状态、baseDataVersion、planRevision 和 digest。分类、事项、重点、用户版本与完成回执整体提交或回滚。源重点在事务外按 entryId 一次分组 / 摘要，历史任务只读取最小 receipt，写入按 1,000 项分批。
- 精确 UUID review 路由独立支持 2 MiB / 10,000 来源选择 / 20 分类映射；sourceKey 最长 160 字符。其他 JSON / 原生认证及阶段 2 的重点、回收站限制保持原值。两端预览每页 50 条，完整计划和选择不截断；切页保留选择。
- 纯共享 `AdmissionCoordinator` 注入本机仓库、UUID、当前游客包及响应式适配，负责显式准备 / 查询 / review / commit；不是后台上传队列。完整冻结包在发请求前 durable 保存。旧 pending 优先恢复，即使游客已有新修订；响应丢失以原任务 / 操作查询，同一操作不能换包。取消 / 过期 / 服务端任务缺失保留原包，可明确新建当前修订预览。
- 仅收到服务器持久 committed 才标记精确账号 + dataset + revision，原包从不自动删除。来源 namespace + 原记录 ID + 内容摘要及最小回执识别连续游客修订：未变来源跳过（即使云端目标已清理也不重建）；改过的来源须明确保留副本或跳过，不静默覆盖云端。完成最小回执保留至账号清理，预览输入到期清理由阶段 7 维护任务承接。
