# 多平台规划与发布

2026-10-30 确认。项目以练习各商店的构建、测试、审核、发布和更新流程为目标；多个客户端共用一套业务后端与 PostgreSQL。本文覆盖旧文档中客户端数量及 PWA 排期的约定，现有业务、身份与冲突规则继续有效。

## 发布顺序

| 顺序 | 平台                                   | 当前安排                                                     |
| ---- | -------------------------------------- | ------------------------------------------------------------ |
| 1    | Web / PWA                              | 优先补齐手机布局、安装、页面缓存与更新体验                   |
| 2    | Chrome / Edge 扩展                     | 优先实现快捷记录、侧边栏，分别走通商店首次上架与版本更新     |
| 3    | 微信小程序                             | 保留现有工程，待用户完成备案后继续发布联调与上线             |
| 4    | Android / Google Play、iOS / App Store | 后续以 Capacitor 复用 Vue 界面，分别练习签名、测试分发和审核 |

## 分工与复用

- `apps/api` 统一负责认证、记录存取、权限、版本检查和数据库迁移；所有客户端访问同一业务 API，不直接连接数据库。
- `apps/web` 同时提供 Web / PWA；移动端先复用它的独立移动构建，`apps/mobile` 维护容器与原生适配，不复制完整业务页面。扩展为快捷入口单独组织小界面。
- `packages` 复用平台无关逻辑；请求、会话存储、导航和设备能力由各客户端适配。出现实际重复后再提取共用 Vue 控件，小程序控件保持独立。
- 各 `distribution/<商店>` 保存上架清单、应用 ID、介绍、截图、版本与提审记录；Chrome / Edge 共用代码，各商店的资料、审核和发布时间独立。
- 每类应用独立构建，工作流按目录和共享依赖识别影响范围。原生工程纳入版本控制；安装包、构建产物和签名私钥不提交，上传凭据放 Secrets。当前仅 `server.yml` 已落地。

## 账号与同步

- 所有端（包括小程序）以同一后端 `userId` 共享云端数据；各端分别登录同一日序账号。PWA、扩展及后续 App 优先接入现有邮箱认证，适配各自的登录回调和会话存储。
- 小程序继续微信登录；微信身份须绑定至同一个日序账号后才能共享其数据，沿用现有绑定 / 合并规则，不自动合并不同账号。
- 在线保存经服务器确认后，其他端通过刷新、回前台或前台轮询获取更新，继续执行版本冲突检查；不新增实时推送或离线写入队列。
- 游客记录、未提交草稿和本机偏好按现有规则保存在各设备；PWA 页面缓存不改变业务保存及同步语义。
